## `.github/workflows/full-desktop-interaction-contract.yml`

### Purpose

The correction campaign extends the established read-only full-desktop proof lane in three bounded ways:

1. JavaScript syntax proof includes the packaged Chromium extension sources and the two Playwright correction scripts in addition to the existing main-renderer and Electron sources.
2. The pytest proof list includes `tests/test_v7_correction_contract.py` and `tests/test_v7_desktop_correction_source.py`, which lock the issue #8 Runtime/RPC, 32-connection, same-PC extension trust, media, widget, geometry, firmware and remote-request contracts.
3. After the mechanical Python/JavaScript gates pass, the same already-registered workflow installs pinned Playwright `1.58.2`, starts an isolated real Lumi source Runtime, and executes the main-renderer and real-MV3-extension proof scripts. This placement is intentional: a workflow introduced only on the PR branch is not treated as executable evidence until registered, so Playwright runs through the existing registered workflow instead.

The workflow remains a read-only proof lane. It does not build an installer, publish a package, create a release, deploy a service, mutate a repository, run on an owner workstation, or perform a production action.

### Permissions

Repository permission remains exactly `contents: read`. Checkout continues to use `persist-credentials: false`. `actions/upload-artifact@v4` uploads only job-local screenshots/logs and does not grant repository mutation authority. No write, actions-management, issue/PR, release/package, environment/deployment, signing, cloud, or external-system permission is introduced.

### Secrets

No repository or external secret is requested or consumed. `LUMIDM_DESKTOP_SECRET` and `LUMIDM_RUNTIME_INSTANCE` are fixed test-only values inside the isolated job. Test download/storage data is created under `${{ runner.temp }}`. The MV3 extension token is generated by that temporary Runtime and disappears with the runner. The proof does not read owner credentials, production pairing tokens, browser cookies, signing material or external service credentials.

### Rollback

Rollback is deterministic and CI-only: remove the correction test paths, extension/Playwright syntax loop, Playwright dependency/install steps, isolated Runtime steps and artifact upload from this workflow. Product source and external systems require no rollback to undo the CI integration. Removing this proof before the correction campaign is complete would reduce assurance and therefore requires equivalent replacement evidence.

### Proof

On the exact PR head the workflow must prove:

- all top-level `static/*.js` and `electron/*.js` syntax;
- all packaged `static/browser-extension/chromium/*.js` syntax;
- both Playwright correction scripts parse;
- the established desktop interaction/release/engine/technician/reliability suites;
- the live v7 Runtime integration contract;
- the v7 static architecture/source contract;
- the real main renderer at exactly 920×650 with no HTML/body/Overview page scrollbar;
- visible titlebar controls are actual hit targets and their bridge actions execute;
- Browser Extension action invokes the bundled extension package and states that same-PC pairing is not required;
- firmware Brand → Model → Source dependency order and source activation;
- the actual fixed-ID Manifest V3 extension loads in Playwright Chromium persistent context;
- automatic local extension identity and the persistent WebSocket bridge connect to the same Runtime;
- at least 14 browser media variants render without a nine-item truncation, authentication error or endless spinner;
- selecting a browser variant creates one pending canonical-Runtime task in the existing widget queue with the 32-connection contract where HTTP applies.

Screenshots and the temporary Runtime log are retained as job artifacts for review.

A green result is mechanical/browser proof only. It does not substitute for independent Sergeant review, Builder packaging proof, Electron BrowserWindow/native Windows identity proof, installer taskbar icon proof, packaged child-process ownership proof or final physical acceptance.
