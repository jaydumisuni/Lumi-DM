## `.github/workflows/full-desktop-interaction-contract.yml`

### Purpose

The correction campaign extends the established read-only full-desktop proof lane in two bounded ways:

1. JavaScript syntax proof includes the packaged Chromium extension sources under `static/browser-extension/chromium/*.js` in addition to the existing main-renderer and Electron sources.
2. The pytest proof list includes `tests/test_v7_correction_contract.py` and `tests/test_v7_desktop_correction_source.py`, which lock the issue #8 Runtime/RPC, 32-connection, same-PC extension trust, media, widget, geometry, firmware and remote-request contracts.

The workflow remains a source/contract test lane. It does not build an installer, publish a package, create a release, deploy a service, mutate a repository, run on an owner workstation, or perform a production action.

### Permissions

Repository permission remains exactly `contents: read`. Checkout continues to use `persist-credentials: false`. No write, actions-management, issue/PR, release/package, environment/deployment, signing, cloud, or external-system permission is introduced.

### Secrets

No new secret is requested or consumed. The correction tests use temporary, test-only loopback credentials generated or supplied inside the isolated test process. They do not read repository secrets, owner credentials, production pairing tokens, browser cookies, signing material or external service credentials.

### Rollback

Rollback is deterministic and CI-only: remove the Chromium-extension syntax loop and the two v7 test paths from the existing workflow. Product source and external systems require no rollback to undo this workflow integration. Removing this proof before the correction campaign is complete would reduce assurance and therefore requires equivalent replacement evidence.

### Proof

On the exact PR head the workflow must prove:

- all top-level `static/*.js` and `electron/*.js` syntax;
- all packaged `static/browser-extension/chromium/*.js` syntax;
- the established desktop interaction/release/engine/technician/reliability suites;
- the live v7 Runtime integration contract;
- the v7 static architecture/source contract.

A green result is mechanical/source proof only. It does not substitute for independent Sergeant review, Playwright visual/interaction proof, Builder packaging proof, native Windows identity proof or final physical acceptance.

## `.github/workflows/roadmap-playwright-proof.yml`

### Purpose

This workflow adds a separate browser/visual interaction proof lane for issue #8. It runs the real Lumi source Runtime on loopback, installs pinned Playwright `1.58.2` plus its bundled Chromium, then executes two bounded scripts:

- `tests/playwright_main_correction.js` proves the approved main renderer at a 920×650 viewport, titlebar hit targets, gear/bell/window actions, 32-connection settings, New Download tabs and Brand → Model → Source firmware dependency behavior. Firmware provider responses are deterministic test fixtures.
- `tests/playwright_extension_correction.js` launches the actual Manifest V3 extension in a persistent Chromium context, verifies its fixed extension identity, automatic same-PC Runtime credential, persistent WebSocket bridge, a 14-variant media panel with no nine-item truncation, and the selected media becoming one pending task in the canonical Runtime.

Screenshots and the Runtime log are uploaded only as CI artifacts for review. The workflow does not package or install Lumi and does not claim native Windows acceptance.

### Permissions

Repository permission is exactly `contents: read`. Checkout uses `persist-credentials: false`. The workflow does not request pull-request write, issue write, actions write, packages, releases, deployments, environments or repository mutation permissions.

### Secrets

No repository or external secret is used. `LUMIDM_DESKTOP_SECRET` and `LUMIDM_RUNTIME_INSTANCE` are fixed test-only values defined inside the isolated job environment. Test download/storage data is created under `${{ runner.temp }}`. The extension token is generated by the temporary Lumi Runtime and disappears with the runner.

### Rollback

Rollback is deterministic: delete `.github/workflows/roadmap-playwright-proof.yml` and the two Playwright proof scripts. No product, release, credential or external service rollback is required. Removing the lane before issue #8 is proven requires an equivalent independent visual/browser execution lane.

### Proof

The exact PR head must:

1. start the real source Runtime successfully;
2. render the main interface at exactly 920×650 with no HTML/body/Overview page scrollbar;
3. prove visible titlebar controls are actual hit targets and their bridge actions execute;
4. prove Browser Extension action opens the bundled-extension path and states no same-PC pairing code is required;
5. prove firmware Brand → Model → Source dependency order and source activation;
6. load the real fixed-ID MV3 extension using Playwright Chromium persistent context;
7. prove local extension identity and persistent browser bridge connection;
8. enumerate at least 14 browser media variants without remaining in a spinner/authentication state;
9. stage a selected variant into the same Runtime as a `browser-pending` queue task with the canonical connection contract where HTTP applies.

A green Playwright result proves browser/render/extension execution only. It does not prove Electron BrowserWindow geometry, Windows AppUserModel/taskbar identity, installer icon, packaged sidecar ownership or signed/Builder release behavior.
